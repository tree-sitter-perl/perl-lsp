# perl-lsp

A Perl LSP server built on ts-parser-perl (crates.io) and tower-lsp.

## Build & test

```
cargo build --release
cargo test                              # unit tests
./e2e/run.sh                            # e2e tests (needs nvim + release build)
gold-corpus/run.pl                      # gold harness (needs release build + installed substrate)
                                        # BUILD IT `--features cpp`: a plain release build
                                        # lang-skips 253 rows (PASS 249 vs 498) — half the
                                        # corpus silently unexercised, reported as skips,
                                        # not failures. Check `lang-skip 0` in the summary.
perl-lsp --dump-package <root> <pkg>    # debug type inference for a package
```

The gold harness (`gold-corpus/README.md`) is an exact-assertion regression
net over real CPAN modules from a snapshot-pinned substrate
(`gold-corpus/local/`). `fixtures/*.json` is the source of truth; statuses:
gold (must hold → FAIL on regression), xfail (known gap → XPASS when a fix
lands, promote the row), provisional (reported, never fails). A crash is
always a hard fail. The suite runs **twice — cold, then warm against the cache
the cold pass wrote** — under a private throwaway `XDG_CACHE_HOME`, so a row
that passes cold and fails warm surfaces as `warm-FAIL` instead of being
invisible (CI always starts cold). Known warm gaps are declared per row as
`"warm": "xfail"`; `--no-warm` skips the second pass. **A warm scan hands out
bag-EVICTED analyses** — decode them through `decode_analysis_parts(.., None,
false)`, never raw `decode_analysis`, or the copy claims a bag it does not have
and every bag-reading projection silently records nothing. Never "fix" a flaky gold
run by clearing the real cache — that deletes the evidence a warm gap exists,
and a PARTIAL clear is worse than none. Run it alongside `cargo test` + `./e2e/run.sh` before
calling a change verified; `gold-corpus/run.pl --emit <cap> <file> <row>
<col>` authors new rows. Known gaps live in `gold-corpus/KNOWN-GAPS.md`.

**Building the substrate (`gold-corpus/local/`)** needs `cpm` and is NOT in the
repo — recipe, incl. the restricted-sandbox mirror workaround, in the
`dev-setup` skill.
**Real-project corpora** (`corpus/README.md`) are a SEPARATE axis from gold:
gold asserts answers, these measure behaviour at scale — wall, RSS, and the
pathologies no fixture reproduces. Every scaling limit in
`docs/scaling-limits.md` came from them, and none reproduced on synthetic
input. `corpus/bootstrap.sh` reconstructs all eight on a fresh box (idempotent;
`corpus/bootstrap.sh "" FHEM` for one). `./kick.sh` opens one in an editor
without typing paths — `--nodeps`, `--dry`, `--debug`.

`$PERL_CORPORA` (default `~/perl-corpora`) is the ONE root both scripts read:
repos in `bulk/`, dependencies in `deps/<name>/`. **Deps live outside the
workspace deliberately** — the walker indexes everything under the root, and
in-tree deps took FHEM from 929 files to 33,912 (97% of them Paws). C/C++
scale work uses its own tree; abseil sits in `~/personal/cpp-bench/abseil-cpp`.

Measuring one of these is a protocol, not a command — the `edit-bench` skill
owns it. Two traps that cost real time: a **single run is not a baseline**
(three minimum; a phantom +400 ms "regression" survived a day on one), and a
**number without a date rots silently** (abseil's warm RSS sat recorded at
34 MB and 47 MB in two ADRs, both ~2x low seven weeks later). Stamp the date
on any measurement you record, or re-measure before citing it.

**`e2e/run.sh` needs `nvim` 0.10+** (the harness calls `vim.lsp.get_clients`);
Ubuntu ships 0.9.5, which fails. Do NOT fall back to "let CI cover it" — run
e2e yourself before calling a change verified. Install recipe (no sudo, no
package manager) in the `dev-setup` skill.

A suite that fails only on its **first** assertion (`no hover result`, then
every later probe passes) is a startup-readiness race, not a logic bug — the
first request is the only one that can arrive before the server is ready.
`lua/test/lsp.lua::open_and_attach` is the gate: it polls `documentSymbol`
until the server answers with content, because a fixed sleep encodes the
box speed that wrote it. If a suite still races, extend that poll to cover the
verb it needs — do not add a sleep, and do not gate on the verb under
assertion or the poll masks the regression the suite exists to catch.

## Architecture

The source tree mirrors the layer DAG — a module's layer IS its top-level
directory, enforced by `src/layering_tests.rs` (down-only imports, the
model's Point-only tree-sitter surface, and single-point grammar access
all fail `cargo test` on violation; an `.rs` file outside a layer
directory — other than `main.rs`/`cst.rs` — fails the walk, so placing a
file places it in the architecture):

```
src/lsp/     LSP adapter      symbols, backend, cli   → LSP protocol types
src/index/   Cross-file       module_index/_resolver/_cache, resolve
                                                      → CachedModule (Arc<FileAnalysis>)
src/build/   Builder          builder, plugins, packs → produces FileAnalysis
src/cst.rs   Typed CST view
src/model/   Data model       file_analysis           → FileAnalysis (serde, bincode-cacheable)
src/util/    Neutral leaf     timings                 → std-only instrumentation (no crate imports; enforced)
```

Oversized modules are directories of focused parts behind an unchanged
public path (`crate::build::builder`, `crate::model::file_analysis`, …);
`mod.rs` holds the type definitions + entry points and glob-re-exports
its parts, so item paths never encode the internal file layout.

See `docs/ROADMAP.md` for the forward design corpus entry point. `docs/adr/file-store-and-resolve.md` covers the landed cross-file unification: single role-tagged FileStore + RoleMask + `refs_to`, plus `resolve_symbol` (cursor→`ResolvedTarget`). That seam is now subsumed by **the resolution CandidateSet** (`docs/adr/resolution-candidate-set.md`): `resolve.rs::resolve(cursor) → CandidateSet` is the one resolution entry point, and goto-def / references / rename / prepareRename / implementations / documentHighlight / linkedEditingRange / completion gathering are projections on the set (`definitions()` / `references()` / `rename_edits()` / `renameable()` / `implementations()` / `highlights()` — the origin-file-narrowed references image, carrying access classification / `linked_editing_spans()` — the co-edit subset rename writes verbatim / `complete()`+`complete_modules()` — completion's candidate SOURCES only; cursor-context slot detection and entity-content walks stay put, see the ADR's honest-boundary list). A new cross-cutting axis (visibility, edges, ranking) goes into CandidateSet construction — never into a handler — and is inherited by every projection by construction. **Visibility is `VisibilityAxis`** (`model/file_analysis/cross_file.rs`): the scope carries its own rule — `IncludeClosure` (C's flat linkage), `SearchPath` (Perl's `@INC`, the asker's own `use lib` roots ahead of the process set, ranked longest-prefix then root order) or `UseMap` (a name-keyed pack's OWN `use` rows + class decls + own namespace: a pinned leaf sees only declarations under that namespace, an empty answer beats a same-leaf stranger; the pin also rides `TargetRef::class_ns` so the references matcher skips files whose same leaf means another class) — so `ScopedLookup` never asks what language it serves, and `VisibilityAxis::for_origin` is the ONE derivation. A new visibility model is a variant there, not a branch in a consumer. Member identity is shape-aware the same value-borne way: `MemberShape` (Callable / Value / Unknown) rides the ref as written, the hop (`ValueHop` vs `MethodHop`, the registry preferring the `field_edge` publication for a value read) and `TargetRef::member_shape` — minted only when the class overloads the name across kinds, so every other class stays name-keyed. **Goto-def surfaces every relevant candidate** (the override family, config-variant macros, the decl→def axis) rather than picking one by heuristic; the origin's OWN evidence — its use-map pin, the token's written shape — is what narrows "relevant", never a ranking guess. Never map `RenameKind`→`TargetRef` inline in a handler; per-feature policy on a target is a method on `TargetRef` (e.g. `supports_cross_file_rename`). Graph walking — one lazy `walk` over the visibility edges (inheritance / bridges / descendants) — landed: `docs/adr/graph-walking.md` (`GraphView`, the closed `EdgeKind` + exhaustive `edges_from`, the Model-layer placement, the file-role/lexical boundaries). Forward work in `docs/prompt-graph-walking.md`: the deferred Scope-node taxonomy, and **instance brands** (per-object dispatch scoping, multi-app Mojo) — spiked and PARKED as a downstream consumer of the long-distance value-provenance tier (`prompt-type-inference-residual.md`), not a standalone feature.

### Rules (read before writing code)

1. **All tree-sitter CST traversal happens inside `build()`.** No other file walks tree-sitter nodes, calls `child_by_field_name`, or uses `TreeCursor`. To add CST-derived data: extend `visit_*` in `build/builder/`. Builder plugins (separate modules taking `&mut FileAnalysis` + `&Tree` + `&[u8]`) are fine — they preserve the single entry point. Multiple post-walk passes inside `build()` are allowed and named (see "Build pipeline phases") for cases needing resolved state.

   **Within sanctioned tree consumers, speak `cst.rs`, not raw nodes.** `src/cst.rs` is the typed view over the CST (rust-analyzer style: zero-copy wrappers via `typed_node!` + `cast`, `NodeExt` for field-text/span/named-children, `pair_nodes` for separator-agnostic pair walking, `call_args` for flat call arguments, `varname_child`/`canonical_container_name` for variable identity, `is_conventional_invocant_scalar` for receiver detection). Each grammar trap is encoded there exactly once. New visitor code uses the typed accessors; re-spelling `child_by_field_name(..).utf8_text(..)` chains or a fresh `kind() == "..."` probe for a shape `cst.rs` already models is a bug. Name-level Perl conventions (`is_constructor_name`, `is_conventional_invocant_name`) live in `src/model/conventions.rs` — pure `&str`, importable by tree-free layers like `file_analysis`.

2. **`model/file_analysis/` is the single source of truth.** All analysis results live in `FileAnalysis`. Query methods belong here. No `tree_sitter` imports.

3. **`lsp/symbols/` is a thin adapter** — `FileAnalysis` types → LSP types. No analysis, no tree walks, no Perl semantics decisions.

4. **`index/module_resolver/` calls the builder, then queries `FileAnalysis`** — never walks the tree directly.

5. **DRY: shared extraction logic goes on `FileAnalysis`.** Two callers needing the same data → one method, both call it.

6. **`lsp/cursor_context.rs` is the position-dependent exception** — gets a tree + source for completion/sig-help context. Does NOT modify `FileAnalysis`.

7. **Every meaningful token gets a ref.** If `ref_at(pos)` returns nothing or returns too-broad, the builder is missing emission. Overlapping refs → `ref_at` returns the **narrowest span**. Common gaps: fat-comma keys in calls (`connect(timeout => 30)` needs its own `HashKeyAccess`), hash literal keys, framework-synthesized entities (Moo `has name` → `HashKeyDef` for constructor, not just accessor).

8. **Plugin-synthesized content is owned by `PluginNamespace`, not Perl classes.** See `docs/adr/plugin-system.md`. Cross-file lookup goes through `ModuleIndex::for_each_entity_bridged_to(class, ...)` — do NOT add parallel reverse indexes (retired: `class_content_index`, `modules_with_class_content`). Plugins have **emit hooks** — `on_use` (walk-interleaved) plus `patterns()`/`on_match` (parse-time, query-declared; walk and fold phases) — declarative, return `Vec<EmitAction>` — and **query hooks** (`on_signature_help`, `on_completion`) — cursor-time, imperative, for shape-dependent behavior. `Silent` / `exclusive` answers suppress native paths when plugin knows native will mishandle the slot. **Walk-phase patterns are declared per plugin but RUN as one query**: every spec that compiles is concatenated into a single tree-sitter `Query` and the tree is traversed ONCE per round, with `pattern_index` (offset by each spec's `pattern_count`) routing each match back to its owner — a `QueryCursor::matches` call is a full tree traversal, so one query per spec walked every file once per spec. Nothing downstream remaps: capture indices are read through `query.capture_names()` and quantifiers through `capture_quantifiers(pattern_index)`, so the combined query and its combined index are the whole translation. A spec whose own query fails to compile is dropped before the concatenation, so one malformed `.rhai` cannot take dispatch out for the rest; `PERL_LSP_PD_NO_COMBINE=1` forces per-spec traversals (the escape hatch and the A/B control) and `PERL_LSP_PD_EQUIV=1` asserts the two paths agree — per-round match streams from the CLI over a real corpus, whole-`FileAnalysis` under `cargo test`.

9. **Provenance: derived refs trace to source** for rename/cross-ref. Constant folding (`my $m = 'process'; $self->$m()`), `has` declarations (accessor + constructor key + internal hash key), import lists, return hash keys → caller derefs (`HashKeyOwner::Sub`), package→file path, inherited overrides.

10. **Never special-case for a particular shape — you are always wrong.** Any code that branches on "is this method named `search`", "does this base equal `DBIx::Class::ResultSet`", "did this come from a plugin vs the real walker", or "is this return-type a String" is encoding a partial enumeration of shapes that match a behavior. The list is always incomplete — tomorrow's case that should match silently doesn't; tomorrow's case that shouldn't match silently does. **Fix:** encode the "wants behavior X" property on the *type / value / witness* itself, so consumers ask the value the question and the value answers. The consumer never sees the shape.

   Recurring forms of this antipattern:
   - **Method-name allowlists** in consumers (`if target_name in {search, find}`). Push the rule onto the *type*: `InferredType::hash_key_class()` for the parametric-arg case. See `docs/adr/parametric-types.md`.
   - **Lossy-string returns** (`Option<String>` for a class name when the source had `Option<InferredType>`). The string is a consumer-side projection, not a return-type contract. Helpers that resolve "what type does this expression produce" return `Option<InferredType>`. Class-name accessors (`class_name()`, `dispatch_class()`, etc.) are caller-side methods on the rich type. Cleanup pass landed; back-compat thin wrappers remain (`method_call_invocant_class`, `resolve_invocant_class_tree`, `invocant_text_to_class`) — they each call the typed sibling and project at the consumer. `method_call_invocant_type` is THE invocant ladder (token-blind receiver value); `method_call_invocant_class` is its dispatch projection (the SUPER/qualified method-token arm + `dispatch_class_of` + DBIC moniker resolve).
   - **Real vs synthetic branches** in worker code (`if synthetic { skip step }`). Synthetic paths run the same body, factored to a function. Termination concerns go on the dispatcher (seen-sets, depth caps) — not on the worker.
   - **Per-base / per-name lookup tables in core** for behavior plugins should own. The plugin trait carries the rule; core dispatches generically.

   The discipline is hard because the special case is always the smallest diff right now. Reaching up to the general path is the larger commit. Do the larger commit anyway — the special case never stays cheap, and provenance / observability / future flavors of the same rule all rot when they're not paying it forward.

### Comment style

Comments earn their keep by explaining **why**, not **what**. The code already says what it does; a comment that restates it is dead weight and drifts the moment the code changes.

- **Write the why:** non-obvious invariants, ordering constraints ("registered first so X claims before Y"), surprising trade-offs, the war story behind a workaround, and pointers to the ADR that owns the decision. One or two tight lines beats a paragraph.
- **Don't narrate history.** No "replaces the old X", "used to be Y", "D3 added", "the staircase deleted", "Spike goals", "Part 6 of the spec", "as Phase 4–6 land". Git remembers; the comment shouldn't. Describe what *is*, not what *was* or what *changed*.
- **Don't restate the architecture.** If it's in this file or derivable from the types, link or omit — don't paraphrase it inline.
- **Don't enumerate every match arm / field in prose** when the code is self-evident; comment only the arm that's surprising.
- A doc comment (`///`) on a public item states its contract; reserve the long-form rationale for the one spot that owns it, not every caller.

When a comment grows past a few lines, that's a smell: either the code wants a clearer name/shape, or the rationale belongs in an ADR under `docs/adr/` with a one-line pointer here.

### File map

- `main.rs` (+ `lsp/cli/` — dispatch, positions, query verbs, heatmap) — entry, CLI modes (`--rename`, `--workspace-symbol`, `--heatmap`, `--dump-package`, `--parse`, `--clear-cache`, `--version`). `cli_full_startup(root)` = "act like LSP just started". `perl-lsp --heatmap <root> [--csv|--html]` emits per-symbol fan-in/fan-out + unreferenced-symbol (dead-code) candidates + a dead-export queue (exported subs with no cross-file use — the relational `unused_exported_syms` view, `docs/adr/relational-ref-index.md`; the same row store SOUND-pre-prunes the fan-in walk for provably-unreferenced names, degrading to the full projection when rows are absent) — fan-in is the CandidateSet's `references()` projection minted at each declaration (never a parallel ref walk), so counts match the references verb by construction; honest over-approximation + failure modes in `docs/adr/heatmap.md`. JSON is the default; `--csv` is the flat table; `--html` wraps the same report in a self-contained offline viewer (treemap heat + fan-in/fan-out butterfly + dead-code queue) whose template is `src/heatmap.html`, embedded via `include_str!` and printed with the report JSON inlined. `perl-lsp --parse <file|->` prints the tree-sitter parse tree (`-` reads stdin) — use it to check node kinds/fields instead of guessing. `perl-lsp --gc-cache <root>` reports the derived store and reclaims interned strings nothing references — a MAINTENANCE verb, not an automatic sweep, because `shred_derived_rows` has standalone autocommit callers whose intern and row-insert land in separate transactions and a sweep between them frees a string the insert is about to reference (retrieval then answers EMPTY, silently); giving the shred one transaction is what would make it automatic. `perl-lsp --clear-cache [<root>]` wipes the SQLite module cache — with `<root>` only that project's hashed cache dir, without it the whole `~/.cache/perl-lsp` tree. Prefer this over `rm -rf` (it canonicalizes `<root>` to the same hash the server writes under).
- `model/file_analysis/` — data model; serde-derived (parts: `core_types`, `ref_table`, `symbol_table`, `pack_facts`, `plugin_facts`, `types`, `dispatch`, `ancestry`, `cross_file`, `imports`, `outline`, `lifecycle`, `surface_feed`, `queries`, `enrichment`, `class_queries`, `cursor_queries`, `invocants`, `hover`, `sym_index`, `completion`). **The struct is a table of lanes, each with one owner** — a new fact goes INTO its lane, never beside it. `RefTable` (`ref_table`) is the reference axis: the refs, every index over them, their `evict()`, their heap arm and their enrichment baseline in one owner — `FileAnalysis::refs()` reads it, the ref-shaped queries delegate to it. `SymbolTable` (`symbol_table`) is the symbol axis on the same shape — the symbols, their name/scope indices, `evict()`, heap arm, enrichment baseline and `row_seeds` — read through `FileAnalysis::symbols()`. `PackageFacts` (`mod.rs`) is one entry per package (parents/uses/framework/requires/role-ness/dynamic-parents) behind `FileAnalysis::packages`, so a per-package join is one lookup. `PackFacts` (`pack_facts`) is the pack lane — receiver names, specialization edges, template params, macro defs, include directives + closure, domain sites, move/control/param regions — and `PluginFacts` (`plugin_facts`) the plugin lane — namespaces, loader facts, diagnostics, gated emissions, app-surface consumers; both default-empty, so a Perl analysis carries two empty sub-structs instead of fifteen empty fields. Each sub-struct assembles its own `heap_estimate` bucket, `FileAnalysisParts` + `new()` move the lanes across as themselves (the symbol/ref axes stay flat vecs the builder appends to and the tables adopt), and `surface_feed` destructures every sub-struct exhaustively — a new lane field is a compile error until its Surface fate is decided.
- `build/builder/` — CST→FileAnalysis. ONLY tree-sitter consumer (parts: `pipeline`, `visit_decl`/`visit_use`/`visit_calls`/`visit_method`/`visit_bless`, `emit`, `chain`, `fold`, `frameworks`, `arity`, `docs`, `infra`, `extract`, `plugin_emit`, `narrowing`, `pattern_dispatch`).
- `build/language_driver.rs` — `LanguageDriver`/`PackDriver`/`LanguageRegistry`, the multi-language serving seam (`docs/prompt-multi-language.md`). `PackDriver::analyze_with_path`'s pipeline is 8 named phases (doc comment on that fn): gather context → transform+parse → extract → remap spans → enrich skeleton → `into_file_analysis` → `emit_return_fuel` → register post-build hooks; remap must precede injection, injection must precede `into_file_analysis`. `emit_return_fuel` is the post-assembly auto-return / implicit-`this` pass (cpp semantics): auto-return chain-fuel always, plus — gated by the pack's `implicit_this_members` capability — implicit-`this->field` read edges AND bare sibling-method-call pinning (`Function` binding → enclosing class).
- `cst.rs` — typed view over the CST (typed wrappers, `NodeExt`, pair walking, call args, varname canonicalization). The vocabulary every tree consumer uses.
- `model/builtins.rs` — THE Perl builtin surface: one sorted table `name → (BuiltinKind, return-type slot, first-arg-type slot)`. Every builtin-aware consumer projects from it — the BUILTIN RoleMask tier's completion source (`Function` rows, wired in `resolve`'s `complete()`), diagnostics suppression (`is_builtin`, any kind), builtin hover's doc gate, and the builder's typed-arg/return seeding. `index/builtins_pod.rs` stays the doc-VALUE store keyed by the same names; `builtins_pod_tests.rs` holds the anti-drift tripwire (perlfunc entries ⊆ table, `Function` rows ⊆ perlfunc). Pure `&str`, Perl-driver-scoped — pack languages never consult it.
- `model/conventions.rs` — Perl name semantics, parsed once: `MethodToken` (FQ/SUPER/main method-token qualifier), `InvocantText` (variable/bareword/`__PACKAGE__`/positional-receiver invocant shape), plus name predicates (constructor, conventional invocant, `__PACKAGE__`). Pure `&str`; no tree-sitter. Never re-derive these shapes with `rsplit_once("::")` / `starts_with('$')` string ops in a consumer.
- `build/cursor_sentinel.rs` — sentinel-reparse member-access cursor context for pack languages (`obj.`/`obj->` → receiver). `docs/adr/cursor-context-completion.md` covers the two-half pack completion (in-scope symbols + sentinel member access + the trigger-char gate); Perl keeps `lsp/cursor_context.rs`.
- `lsp/cursor_slot.rs` — the cursor `Slot` taxonomy (`docs/adr/cursor-slots.md`): one vocabulary ("what kind of hole is the cursor in") over both `cursor_context` (Perl) and `cursor_sentinel` (pack). `detect_slot` answers identity (Member/Key/Identifier/Import/ModulePath); `detect_call_slot` answers arg-position orthogonally. Consumers switch on `Slot`, never on language.
- `lsp/symbols/` — LSP adapter, one part per verb family (`outline`, `navigate`, `completion`, `hover`, `signature`, `tokens`, `diagnostics`, `code_actions`).
- **Pack diagnostics** (`docs/adr/php-diagnostics.md`): pack documents publish through `pack_diagnostics`, whose symbol lanes (`unresolved-method`, `undefined-property`, `non-public-access`, `arity-mismatch`, `undefined-variable`, `undefined-type`, `unused-import`, `unused-variable`, `deprecated`) read only facts packs mint — `Ref::arg_count`, `Symbol::arity`, `Ref::binding`, the use-map pins — plus the pack's declared conventions (`receiver_names`, `implicit_variables`, `catch_all_methods`, `enum_members`, `class_literal_member`, `types_are_capitalized`). The receiver is THE dispatch projection (`method_call_invocant_class`); every lane carries a named silence rule for what it cannot see, and a new false positive is fixed at its source (a read the skeleton should not have minted) before it is filtered. The undefined-type lane runs only on a settled pack index: `--check` by construction, the editor through the family's ready gate (`index_ready.pack.is_open()`) — never a literal `false` at a publish site. Its diagnostic carries the declaring namespaces as `data.candidates`, which the import quick-fix (`code_actions::make_import_type_actions`) turns into the pack's `import_template` inserted after the last `PackFacts::import_rows` row. **The extractor registers every class body** (`register_class_body`: the scope's package is the class, and each `receiver_names` entry is witnessed as `ClassName(class)` at the body scope) — that one seam is why `$this->prop->m()` chains, signature help and the lanes agree. Pack signature help is `cursor_sentinel::call_at` (the pack's `call_shapes`, walked on the document's own tree) + `signature_from_source` (the declaration's own text); the backend routes pack documents there by `DriverCaps::pack_signature_help`.
- `index/resolve/` — the resolution CandidateSet (`resolve(cursor)` + the gd/gr/rename/implementations projections), `refs_to`, `RoleMask` (OPEN/WORKSPACE/DEPENDENCY/BUILTIN), import-binding classification. All cross-file queries route here.
- `index/module_index/` — cross-file dep API, `CachedModule`, `SubInfo`, reverse index (`func → modules`). The reverse-index buckets are `ModuleBucket`, not bare vecs: membership is O(1) because a per-insert linear scan makes bulk feeds quadratic in bucket size, and the worst bucket is the common one (`new`, declared by every module). `ModuleEdgeIndexes::feed` / `publish_spec` / `publish_child` are the ONLY edge write paths, and each marks the member fed — `purge_module` skips its O(all-buckets) sweep for a module that was never fed, so an unmarked publication would silently outlive its file.
- **A verb indexes only the language families its answer can consult.** `LanguageScope` (`build/language_driver.rs`) is declared by the VERB and read by the indexer, which never asks what kind of query it serves: `of_file(path)` for a verb with a target, `All` for one that sweeps the workspace (`--check`, `--heatmap`, `--workspace-symbol`, and `--batch` — whose requests arrive after startup). Over-indexing is wasted work; UNDER-indexing is a quiet wrong answer, because an unattached pack sub-index does not answer empty — `lookup_for` routes that language to the Perl hub. Adding a verb means choosing its scope.
- **Startup is not one thing.** The server's `initialize` indexes nothing: it sets the workspace root and returns, the workspace index is lazy (first `didOpen` → `spawn_blocking`) and `@INC` resolution is on-demand on the resolver thread. `cli_full_startup` does all of it synchronously, because a CLI verb has no partial answer to give. Comparing "server ready" to "CLI ready" compares two different states; when a CLI verb is slow, attribute it with `PERL_LSP_PHASE_TIMING` before concluding the CLI takes a different path — it takes the same one, eagerly.
- `index/module_resolver/` — background `std::thread`, in-process parsing, workspace indexing (Rayon) (parts: `thread` resolver loop, `inc` @INC tier, `index_perl`/`index_pack` bulk indexers, `persist` residency policy + writer harness).
- `index/pack_invalidator.rs` — `PackInvalidator`, the ONE owner of pack-file invalidation: serialization lock, H9-2 bulk-index defer/reconcile coordinator, H9-1 source-generation guard, and the single `is_consumer` include-closure rule (registered storm + open-doc refresh, both behind the surface gate). Entry points: `file_changed(path, deleted) → InvalidationOutcome` and `begin_bulk_index`/`finish_bulk_index`; the Backend only forwards events and publishes the outcome's open URIs.
- `index/module_cache/` — SQLite (schema v10, ref rows v6; parts: `conn` opens, `schema` DDL + generation gates, `blob` codec + stamps, `rows` relational store, `stubs`, `warm` scans): bincode+zstd FileAnalysis blobs PLUS the relational row store (`files`/`strings`/`refs`/`syms` tables, `docs/adr/relational-ref-index.md`) — both row families shredded from each analysis in ONE call/txn with its blob (`shred_derived_rows`; `files` presence is the single shredded marker), `REF_ROWS_VERSION` governs BOTH row formats (wipe+re-shred, never a blob drop; the version check shape-probes the tables so a lying stamp still rebuilds). `refs` rows are `(name_id, file_id)` pairs, `WITHOUT ROWID` so the table IS the name index — every reader is a set-valued projection onto exactly that pair, and the shredder dedups in memory so the STATEMENT count falls with the row count. There is deliberately no occurrence `count` column: a row count is a CANDIDATE count, and the over-approximation is what makes `unused_exported_syms` sound. String interning is SELECT-first with a writer-lifetime memo keyed by `meta.strings_generation` (bumped by `clear_derived_rows` and the row-format rebuild) — a stale `str_id` after a wipe writes rows nothing joins to, which fails SILENTLY. `refs_to` retrieval is `ref_candidate_files` (refs UNION syms so declaration-only files are candidates too); the matcher runs on the rehydrated analysis. workspace/symbol composes resident sweeps + `sym_rows_matching` (workspace tier only). Resident index copies are bag+refs+SYMBOLS-evicted after persist — readers ask for the AXES they read: `bag_present` (bag), `symbols_present` (symbols), `refs_present` (refs+symbols, the backward-walk matcher's axes — its rehydrate lane retains BAG-STRIPPED copies in the same byte-capped LRU, one budget), `whole_present` (everything; `is_fully_resident` is the gate). Every reader rehydrates on a stripped axis, never resident-or-empty. `refs_to` runs the matcher on `matcher_view` — the refs view, upgraded per-file to whole when a name-matching ref's verdict isn't baked (`Ref::match_verdict_baked`: unstamped MethodCall / unowned hash key — the bag-consulting fallback arms). `PERL_LSP_NO_EVICT` keeps copies whole; `PERL_LSP_REF_ROWS=0` forces the resident-only walk — pair them. `--refs-parity <root> [--sample=N]` is the A/B migration net. **Warm stubs**: the pack warm scan registers from the `stubs` table (feed+specs+Surface+stripped skeleton per file, written by the persist writer in the same chunk txn) via `warm_pack_stream_with_stubs` — no full-blob decode; declined lanes (rows missing / NO_EVICT / decode break / `stub_version` gate) fall back to a point full-decode that backfills the stub. Any modules-row rewrite deletes the path's stub (inside `save_to_db`/`save_blob_to_db_stamped` — writers can't forget); hard-clears wipe via `clear_derived_rows`.
- `model/surface.rs` — the span-free Surface (`docs/adr/storage-engine.md`): `Surface::project(&FileAnalysis)` = the cross-file-VISIBLE projection (packages/methods/values/macros/includes/imports/exports/bridges; `despan` sanitizes InferredType), equality = "no cross-file-visible change". `FreshnessIndex` (fingerprint + provided names per file — never full Surfaces resident) answers `record → SurfaceVerdict` and `dirty_consumers`; `ModuleIndex::record_surface[_value]` canonicalizes the key. Consumers: `Backend::republish_open_docs_in` (Perl open docs re-enrich on Changed, via `FileStore::enrich_open`; the open doc's record is its build-time `Document::baseline_surface`) and `PackInvalidator::file_changed`'s gate (Unchanged header edit → one-file re-analysis, no consumer storm — registered and open consumers alike). R1, compiler-enforced on the FileAnalysis side: `FileAnalysis::surface_feed` destructures every field (no `..`), so a new FileAnalysis field fails to compile until classified projected-or-reasoned-discard; a Surface field addition still requires an equality-net arm — one smuggled span collapses the firewall.
- **Residency discipline (read before adding ANY indexing/registration path).** Resident index copies are STRIPPED; whole copies are budgeted exceptions. The seams: `FileAnalysis::evict_to(Residency)` is the one speller of the strip; `ModuleIndex::prepare_pack_parts` / `prepare_workspace_parts` are the one spellers of reads-whole-before-evict (feed + Surface project from the whole analysis, THEN evict, then the arc mints) — never re-spell that sequence. Whole-copy registration (`register_symbols`, `register_workspace_resident`, …) is policed by `layering_tests::whole_copy_registration_sites_are_allowlisted`: a new call site fails the test until you add it with a residency bound; bulk paths use the stripping/parts APIs instead. A post-bulk-index **residency tripwire** counts fully-resident pack copies against the deliberate whole-copy sites (`count_fully_resident` vs the `expected_whole` counter) and errors/debug-asserts on unexplained pins — functional tests can't see a RAM regression, this can. Bounded caches only: `PackBagCache` and the enrichment overlay (`enriched_snapshot`, 128 MiB + 64 entries) are byte-accounted; a new derived-copy cache must be too. Deferred-write loops share `write_in_chunks`; warm-scan row validity shares `classify_row_generation`. Known unbounded residuals (watcher re-registration; the @INC tier strips cold AND warm in long-lived processes — one-shot CLI keeps warm copies whole for wall; writer fallback is byte-capped at 128 MiB/writer) are in `docs/prompt-storage-residuals.md`.
- `util/timings.rs` — **all profiling/timing instrumentation lives here.** Per-module build timings (`--timings` / `PERL_LSP_TIMINGS`, slowest-first report) and per-phase timing (`timings::phase`, `timings::PhaseGuard` for a region that can't take a closure, plus the `tphase!` call-site sugar, gated by `PERL_LSP_PHASE_TIMING`). `cli_full_startup`'s phases are named `cli::*` — that is how a CLI verb's startup cost is attributed. **A printed line per entry only suits a region entered ONCE per run**; a per-FILE region accumulates instead — `bphase!` routes to `ghost_stats::timed` (reported under "accumulated time"), and a per-file quantity goes to `ghost_stats::count_by`. Printing them cost a 138k run 3.2M lines and 43 minutes, measuring a run that no longer resembled the one being measured. Don't hand-roll env-gated `eprintln!` timers or counters — route through here so the gate is read once and the output format stays uniform.
- `bench/` — the measurement stack (`bench/MEASURE.md` is its manual). `bench/measure.sh` sweeps the real corpora into tall JSONL (`{kind,name,value,unit}` per fact, raw, never aggregated at collection); `bench/load.sql` / `report.sql` slice it in DuckDB; `bench/baselines.jsonl` is the CHECKED-IN KPI record (curated by `seed-baselines.py` after a trusted sweep — every row carries sha/dirty/host/n/spread, and `baseline-check.sql` flags only moves that clear both sides' measured noise; counters are diagnostics and are never baselined). `bench/lsp_bench.py` plays `bench/scenarios/*.json` editing scripts over stdio for the editor surface (per-verb latency, didChange→diagnostics push, RSS, cold/warm startup) and `--jsonl` lands its rows in the same store; `bench/editor-baseline.sh` is its 3-rep wrapper (QUIET BOX ONLY — run lines record loadavg). The binary's machine-readable sinks: `PERL_LSP_GHOST_JSON[_DIR]` (every counter + the per-file check lanes with inclusive AND exclusive time), `PERL_LSP_TIMINGS_JSON[_DIR]` (every module's parse/build), `PERL_LSP_HEAP_JSON[_DIR]` (per-file heap-bucket composition — the whose-refs lane; resident composition at the call site, NOT peak attribution). `_DIR` variants write one file per process, which is how gold and e2e feed the same store. `bench/RESULTS.md` is the append-only findings ledger. The repeatable protocol (project prep, quiet-box discipline, traps) is the `edit-bench` skill (`.claude/skills/edit-bench/SKILL.md`).

## Cross-file resolution

- `ModuleIndex` runs a dedicated `std::thread` for FS I/O (never blocks tokio). The shared mutable state (cache, edge indexes, resolve queue, generation counters, loader shapes, bag-cache cell) is ONE struct — `IndexCore` (`index/module_index/index_core.rs`) — held via a single `Arc` by both `ModuleIndex` (async side) and the resolver thread; shared-state operations are `IndexCore` methods so the two sides can't drift.
- `CachedModule { path, analysis: Arc<FileAnalysis> }` — full FileAnalysis survives module boundary (refs, type_constraints, call_bindings, framework_imports, per-package facts). `SubInfo<'_>` view gives ExportedSub-style accessors.
- Reverse index: `DashMap<func_name, Vec<module_name>>` for O(1) exporter lookup.
- **A module name maps to a SET of files, not one file.** The @INC tier enumerates every root providing a name (`resolve_module_paths`, @INC order) and parses every provider; they land in `IndexCore.all_defs`, the same candidate relation the workspace tier uses, and the name-keyed `cache` slot holds the derived winner. The tiers SHARE the relation but not the winner — project code shadows an installed copy, so the workspace winner pick filters to `registered_names` (the front-door registrations). `modules` is keyed `(module_name, path)` so two providers persist.
- SQLite cache per project at `~/.cache/perl-lsp/<hash>/modules.db` (honors `$XDG_CACHE_HOME`). `EXTRACT_VERSION` bump triggers priority re-resolution without dropping the table. To nuke it (e.g. before a cold-start repro), use `perl-lsp --clear-cache [<root>]` — not `rm -rf`.
- **Plugin fingerprint** — bundled plugin sources + every `.rhai` in `$PERL_LSP_PLUGIN_DIR` are hashed. Mismatch on startup hard-clears modules table (same machinery as `validate_inc_paths`). Editing a plugin invalidates cache so QA isn't served stale blobs.
- Async handlers only call `_cached` methods (zero I/O).
- After resolution, diagnostics refresh for all open files (clears stale false positives).

### Cross-file enrichment

`enrich_imported_types_with_keys()` on `FileAnalysis` propagates imported return types and hash-key OWNERS: pushes `TypeConstraint`s for call bindings to imported funcs, and stamps `HashKeyOwner::Sub{producer_pkg, func}` onto the consumer's `HashKeyAccess` refs. It does NOT inject synthetic `HashKeyDef` symbols — the producer's real def is the single source, and a location-less stub reappears as a phantom `0:0` decl. The lazy twin of the same rule is `deferred_hash_key_owner` (`cursor_queries.rs`), which carries the unenriched workspace-file case; the eager stamp serves open docs only. Idempotent: the `SymbolTable` / `RefTable` enrichment baselines and `base_witness_count` are sealed after initial build; enrichment truncates back to baseline before appending. `rebuild_enrichment_indices()` rebuilds index maps after. For OPEN documents, **`FileStore::enrich_open` is the ONE enrichment writer**: it clones the doc's analysis off the store lock, enriches, and swaps the derived copy in via a short ptr-guarded write — `publish_diagnostics`, the resolver refresh callback, and the cold-open heal all read the artifact it returns (`refresh_open_diagnostics` is the shared bulk spelling); no handler mutates a stored analysis. Freshness records read `Document::baseline_surface` — the build-time, pre-enrichment projection — so surface verdicts are enrichment-invariant by construction (no record-before-publish ordering). Closed workspace/dependency files answer enriched through **the R4 overlay** (`ModuleIndex::enriched_snapshot` / `CrossFileLookup::enriched_present`): derived fingerprint+generation-keyed copies, byte-capped, cycle-guarded, consulted FALLBACK-ON-MISS by `query_sub_return_type`'s imported recursion and the `PackageSymbol` cross-file primary (and by `--check`/`--dump-package`). Never hand-roll a deep-copy+enrich dance — route through the overlay. The overlay's private copy is a `clone`, not a serde round-trip: the round-trip cost 11x more AND silently reset the `serde(skip)` flags (`degraded`, the eviction markers), so an enriched copy of a degraded analysis claimed to be whole. What a build actually costs is measured in `docs/adr/enrichment-build-cost.md` — copy 3.8%, cross-file provider chase 61.6% (that share PREDATES the resident-copy export gate, which took the chase from 1,541 ms to 241 ms; see `docs/adr/skipping-cross-file-work.md`) — which is why level-indexed enrichment's stated prerequisite (shrink the copy) would not have unblocked it. Type/method resolution through inheritance survives this via the `PackageSymbol` query-time walk; **dispatch-verb resolution** survives it via the query-time `ReceiverGated` seam (`FileAnalysis::applicable_dispatches`, resolved in `refs_to` / goto-def — `docs/adr/receiver-gated-dispatch.md`). `ClassIsa`/`param_types` ancestry-gated *emission* rides the same seam as a `GatedEmission` (`plugin_facts.rs`, materialized by `materialize_gated_emissions`); the per-manifest applicability matrix is in `docs/prompt-enrichment-inheritance-residual.md`.

## Type inference (witness bag)

**The bag is the only source of types.** Type production is `bag.push(...)`; type consumption is `bag_query_attachment(att)` through `ReducerRegistry::query`. There is no second source. `Builder::infer_expression_type` is gone; closed-syntax cases live in `expr_payload`'s match called by `emit_expr_witness`. `Builder.resolved_returns` is gone; walk-time synthesis pushes `Symbol(sid)` witnesses directly. See `docs/adr/bag-canonical.md` for the load-bearing decisions; `docs/adr/structural-shapes.md` for structural hash shapes (`HashWithKeys`, `Projected` drills, mutation extension, the whole-story trust gate).

**Edges, not values.** If a registry query on attachment `A` already resolves through an edge chase, do NOT re-push the materialized `InferredType(t)` onto `A` as a "cache." The registry's chase IS the canonical flow; the materialization is a parallel store that drifts. Every published witness is either (a) a source value the walker uniquely knows (a literal's type, a plugin's declaration, a framework's `ReturnExpr`) or (b) an `Edge` to another attachment.

**Two strict phases:**

1. **Collect** in `Builder::populate_witness_bag()`: mirror every `TypeConstraint` as Variable witness; push `HashRefAccess` from `$v->{k}` refs; push `mutation` Facts on hash-key writes; push `Symbol(sid) → Edge(Expr(last_expr_span))` for each Sub/Method scope without explicit returns (the implicit-return chain).

2. **Reduce** via `ReducerRegistry` in `src/model/witnesses/`. Reducers in registration order — earlier entries claim first:
   - `PluginOverrideReducer` — Plugin-priority `Symbol(_) + InferredType` short-circuit. `WitnessSource::priority()` returns 100 for `Plugin(_)`; 10 for everything else.
   - `ReturnExprReducer` — `WitnessPayload::ReturnExpr(_)` shapes: `Concrete` / `Receiver` (substitutes `q.receiver`) / `Operator(RowOf(_))` / `UnionOnArgs` (dispatches `q.arity_hint`). See `docs/adr/return-expr.md`.
   - `SymbolReturnArmFold` — `SymbolReturnArm(sid)` attachment; folds per-arm `Edge(Expr(body_span))` witnesses via `resolve_return_type` (1+ arms agree → `Some(t)`, disagree → `None`). `Symbol(sid)` carries one `Edge(SymbolReturnArm(sid))` chain witness per arm so consumers querying the symbol's return materialize through.
   - `SlotTypeFold` — claims the dedicated `SlotType{..}` shape; order here isn't load-bearing.
   - `BranchArmFold` — agreement across ≥2 `branch_arm`-source `Edge` witnesses on `Variable` / `Expr` for ternary RHS.
   - `FrameworkAwareTypeFold` — folds `TypeObservation` (rep / class / bless / numeric / regex / string) using package's `FrameworkFact`. Class-identity dominates rep when frameworks agree (Mojo `$self->{x} = ...; return $self` keeps `ClassName`). Temporal: skips witnesses past the query point.
   - `ExprReturn` — `Expr(_) + InferredType` latest-wins.
   - `PackageSymbolReducer` — `PackageSymbol{package, name}` primary fallback. Inheritance + cross-file bridges resolve via `query_rec`'s structural recursion on the same attachment shape, with inheritance edges (`PackageSymbol{child, m} → Edge(PackageSymbol{parent, m})`) pushed by the writeback so the registry walks them like any other edge.
   - `TypeNameReducer` — disjoint class-keyed fallback shape (typedef/using aliases); order here isn't load-bearing.
   - `DomainCoherenceFold` — the disjoint `Field{..}` shape (int-used-as-enum domain vote); order here isn't load-bearing.
   - `SubReturnReducer` — `Symbol(_) + InferredType` latest-wins, runs last; backstop when no higher-priority reducer answered.

**Single shared query path.** `query_variable_type(bag, scopes, framework, var, scope, point)` and `query_sub_return_type(bag, symbols, name, arity_hint, ...)` in `model/witnesses/query.rs` are the only scope-walk + framework + reducer dispatch sites. `FileAnalysis::inferred_type_via_bag` / `sub_return_type_at_arity` (query-time) and `Builder::bag_query_attachment` / `bag_query_expr_span` (build-time) are thin wrappers over the registry. Identical rules in both by construction.

**`TypeConstraint` is an input-parameter shape.** The struct exists so callers can package `(variable, scope, span, inferred_type)` for `push_type_constraint(tc)`, which translates it into Variable witnesses on the bag. There is no `Vec<TypeConstraint>` field — the bag is the only storage. Enrichment truncates the bag back to `base_witness_count` before re-deriving.

**Query entry points** (call these, not internal helpers):

- `inferred_type_via_bag(var, point)` — variable type at a point.
- `sub_return_type_at_arity(name, arity)` — sub return type (locals + imports).
- `method_call_return_type_via_bag(ref_idx)` — Expression-attached return type (lets `$r->get('/x')->to('Y#z')` resolve `->to`'s receiver without an intermediate variable).
- `find_method_return_type(class, method, module_index, arity)` — class-keyed method return type. Thin wrapper that builds a `PackageSymbol{package, name}` `ReducerQuery`; the registry handles inheritance walks and cross-file bridges.
- `mutated_keys_on_class(class)` — **no production caller** (tests + the layering allowlist only), and every `HashKeyDef` minting site passes `is_dynamic: false`. The dynamic-key lane is dormant, not wired: observed writes feed structural SHAPES, not completion. Delete it or revive it deliberately; do not cite it as a live feature.

**Test-only:** `FileAnalysis::inferred_type(var, point)` is raw-state introspection (no framework/branch/arity rules), `#[cfg(test)]` — tests asserting on raw builder state only; `layering_tests::inferred_type_has_no_production_caller` pins it. Use `inferred_type_via_bag` everywhere else.

**Adding type behavior = adding a reducer.** Never bypass the bag with direct `InferredType` writes or parallel query helpers. New fact → push a witness (`Edge` if it routes to an existing source); new fold → write a reducer.

**Cache durability:** `WitnessBag` and `packages` (the `PackageFacts` table) are `#[serde(default)]`, ride bincode+zstd cache blob. Bump `EXTRACT_VERSION` on shape/rule changes.

### Build pipeline phases

`build_with_plugins()` in `build/builder/pipeline.rs` runs in fixed order. Each pass consumes state the previous produced.

1. **live walk** (`visit_*`) — emits Symbols/Refs/Scopes/TypeConstraints, queues plugin emissions, records `ReturnInfo`s (scope + arity branch + body span — no walk-time types). Walks emit `Expr(span)` witnesses via `emit_expr_witness` at every meaningful expression node (literal types directly, name-dependent shapes as `Edge` payloads pointing at `Variable` / `Symbol` / `Expression`).
2. `resolve_variable_refs()` — scalar refs → `Symbol` bindings (`Ref::binding` is the one home for every resolution outcome; read via the `Ref` projection accessors).
3. `resolve_hash_key_owners()` — HashKeyAccess → HashKeyOwner via TC types.
4. `apply_type_overrides()` — plugin manifests push **Plugin-priority** witnesses on `Symbol(sub_id)`. The `PluginOverrideReducer`'s priority short-circuit (Plugin > Builder) makes them dominate every other reducer. Provenance is recorded as `TypeProvenance::PluginOverride` so `--dump-package` can answer "why does this return X?". Runs BEFORE the worklist fold so dependent inference sees overrides via the bag.
5. `populate_witness_bag()` — one-shot bag seed. Mirrors walk-time `TypeConstraint`s as Variable witnesses; pushes `HashRefAccess` Observations from `$v->{k}` refs; pushes `mutation` Facts on hash-key writes; pushes `Symbol(sid) → Edge(Expr(last_expr_span))` for each user-defined Sub/Method scope without explicit returns (the implicit-return chain). Bag is canonical after this.
6. `fold_to_fixed_point(chain_idx)` — **the worklist fold**. Each iteration runs `ChainTypingReducer::PreFold` (assignment + return-arm refresh) followed by `resolve_return_types`: `emit_arity_return_witnesses` (re-emittable per-Symbol UnionOnArgs publication for arity-discriminated subs) → `emit_method_call_return_edges` (re-emittable `Expression(refidx) → Edge(PackageSymbol{...})` for known invocants) → `seed_return_types_from_bag` (pure read; queries `Symbol(sid)` per Sub/Method scope, builds the name-keyed `return_types` map for downstream consumers, preserves `PluginOverride` / `Delegation` provenance) → `write_back_sub_return_types` (pushes `PackageSymbol{package, name} → Edge(Symbol(sid))` for primaries; plugin-namespace bridges; inheritance edges) → `propagate_call_bindings_to_constraints` → `fixup_call_bound_hash_key_owners`. The loop exits when the snapshot — per-Sub registry answer + bag len + invocant cache size — stops moving; `MAX_FOLD_ITERATIONS = 64` is the debug-only safety net. After the lattice settles, `ChainTypingReducer::PostFold` runs once to fill `invocant_class` on `MethodCall` refs.
7. `resolve_tail_pod_docs()` — POD docs for subs lacking preceding doc.
8. `FileAnalysis::new(...)` — construct FA, build indices; finalize runs the MCB→bag bridge (`emit_method_call_binding_edges`: each `$var = $invocant->method()` binding → `Variable → Edge(PackageSymbol)` witness, chased lazily by the registry with whatever index the query holds; enrichment re-runs the same bridge).
9. `fa.finalize_post_walk()` — seal `base_*_count` for idempotent re-enrichment.

`Builder::resolve_invocant_class_tree` is the **single** build-time symbolic-execution function (chain typing, return-arm refresh, invocant filling); `invocant_type_at_node` is its node-kind dispatcher. Adding a second is wrong; add cases. Query-time expression typing is **tree-free**: `FileAnalysis::expr_type_at_span(span, module_index)` is the one entry — it reads the `Expr(span)` witnesses the builder records per invocant (`emit_invocant_expr_witnesses` PostFold pass) plus exact-span call-ref returns, materializing edges through the registry. `method_call_invocant_class(r, module_index)` resolves an invocant via it (no tree). `resolve_expression_type(node, …)` is now a thin `node → span → expr_type_at_span` adapter, degrading to a node-kind walk only for raw-cursor/incomplete-ERROR completion. There is no second structure-discovery walker to "keep in sync."

### Worklist invariants

The fold driver in step 6 is the only place type inference iterates. Adding a new fact-fold means **adding a reducer**, not changing the driver:

- **Reducers are stateless.** A `WitnessReducer` claims a `WitnessAttachment` shape (`Symbol(_)` / `Variable{..}` / `Expression(_)` / etc.) and folds the witnesses for that attachment into a `ReducedValue`. They live in `model/witnesses/reducers.rs` and register through `ReducerRegistry::with_defaults()`. The worklist driver never special-cases a reducer — it just runs the registry on each attachment.
- **Witnesses are monotone.** Once a witness is in the bag, it stays. New facts append; no reducer rewrites or deletes another's witness. Termination follows from the lattice (`InferredType` is a finite enum, ~12 variants) plus the snapshot check: when nothing new appears in two consecutive iterations, the fixed point is reached.
- **Edges, not values** (stated under "Type inference" above). The two structural enforcers: mirrors between attachments go through `Edge(target)` — see writeback's `PackageSymbol{package, name} → Edge(Symbol(sid))`, the canonical shape ("the edge IS the mirror") — and re-emittable passes clear-and-emit (next bullet). A materialized `InferredType` re-pushed onto an edge-reachable attachment is the parallel-store bug the staircase deleted.
- **Re-emittable passes are clear-and-emit.** Every builder pass that legitimately re-derives its bag contribution per iteration calls `WitnessBag::remove_by_source_tag(...)` at the start of every run, then re-pushes from current state. Current re-emittable tags: `arity_detection` (per-Symbol UnionOnArgs), `method_call_return` (call-site `Edge(PackageSymbol{...})`), `local_return` / `plugin_bridge` / `inheritance` (writeback), `call_binding` (propagator). Chain typing's TC-existence check serves the same role for chain-assignment witnesses. Anything else added to a fold step that pushes witnesses MUST follow this idempotency pattern or the worklist will spin.
- **Walker only observes.** No walk-time function returns a type without first emitting the witness. `emit_expr_witness` is the canonical entry; `expr_payload` carries the closed-syntax bake for literals and the `Edge` payloads for name-dependent shapes. Consumers that need a type at walk time do `emit_expr_witness(node); bag_query_expr_span(span)` — emit first, query after.
- **Source priority breaks ties.** `WitnessSource::priority()` returns 100 for `Plugin(_)` and 10 for everything else. The `PluginOverrideReducer` runs first in the registry and short-circuits when it sees a higher-priority witness on a Symbol attachment. New "this answer must dominate" sources go on this priority axis — never as a special-case branch in another reducer.
- **`TypeConstraint` writes go through `push_type_constraint(tc)`.** The struct is an input-parameter shape; the helper translates it into Variable witnesses on the bag. No `Vec<TypeConstraint>` field exists — the bag is the only storage. Direct bag pushes that bypass `push_type_constraint` are allowed (it's just a sugar wrapper) but miss the `ClassAssertion` / `FirstParamInMethod` Observation companions; prefer the helper for `InferredType::ClassName` / `FirstParam` payloads.

## tree-sitter-perl gotchas

Inspect any snippet's CST with `perl-lsp --parse <file>` (or `echo '...' | perl-lsp --parse -`) rather than guessing node kinds/fields.

- `subroutine_declaration_statement` / `method_declaration_statement` — fields: `name`, `body`, `lexical`.
- `variable_declaration` — `variable` (single) or `variables` (paren list).
- `package_statement` / `class_statement` / `use_statement` — field: `name` / `module`.
- `function_call_expression` (with parens) vs `ambiguous_function_call_expression` (no parens, includes `bless { ... }`).
- `method_call_expression` — `invocant`, `method`.
- `scalar` / `array` / `hash` = sigil + varname.
- ~~`child_by_field_name("right")` on `assignment_expression` returns `(` paren~~ — **no longer true on ts-parser-perl 1.1.4** (re-measured 2026-08-17): `my $x = (1+2)` gives `right: binary_expression`, `my @a = ('a','b')` gives `right: list_expression`. Use the field. Kept as a struck line because workaround code written against the old behaviour (iterating `named_child(i)` to dodge a paren that never arrives) still exists and reads as deliberate.
- `require Foo::Bar` is `require_expression` with a bare `bareword` child — NO `module:` field, unlike `use_statement`; match structurally. `require 5.010` / `require v5.36` are a separate kind (`require_version_expression`), and `no Foo;` parses as `use_statement` (no `no_statement` kind exists).
- `map BLOCK LIST` and `map EXPR, LIST` are both `map_grep_expression` with a `callback:` field; the block form's callback is a real `block` node — NOT the anonymous-hash misparse the Perl ambiguity would suggest.
- `parenthesized_expression` is **not a Perl grammar kind YET** — it is absent from ts-parser-perl 1.1.4's `node-types.json`, so those arms are inert today, but the kind is **coming in the next parser release** (slow-walked: it's a breaking change, and nearly every tree-sitter grammar needs this wrapper or aliases and fields misbehave). The ~27 Perl-side arms are deliberate forward-compat — **do not "clean them up"**; they become correct the day the parser lands. Until then paren lists are `list_expression` and single-expression parens are invisible. Pack-side comparisons are live now — it is already a real tree-sitter-cpp kind.
- `child_by_field_name("hash")` on `$obj->{key}` returns None — use first named child.
- ERROR nodes wrap subs in incomplete source — scan ERROR children for patterns like `my ($self) = @_`.
- **Fat-comma `=>` has NO code semantics — it is a comma that autoquotes a bareword LHS.** `a => 1` is *identical* to `'a', 1`; `{ A => 1, B => 2 }` is identical to `{ 'A', 1, 'B', 2 }`. So for **correctness** you must **never** gate pair-list walking (`use` import args, `%EXPORT_TAGS`/`%hash` literals, `use constant {…}`, Moo `has` options, Sub::Exporter `exports`/`groups`) on the `fat_comma`/`=>` node — that silently drops the plain-comma spelling (this exact bug hid `use constant { 'GAMMA', 3 }`). Treat the `{…}`/`(…)` as a **flat positional sequence**: pair `elem[2k]`→key, `elem[2k+1]`→value, autoquoting bareword keys, identically whether the separator was `,` or `=>`. Requiring `=>` is a rule-#10 shape-branch; use the shared positional-pair-walking helpers rather than re-deriving.
  - But `=>` **does carry *human* semantics** — a human writes it to signal "the LHS is a key/label, the RHS its value." That's a legitimate **hint** we may lean on in the future (e.g. to disambiguate an otherwise-ambiguous list, or to bias which element is the "name"). Allowed as a *heuristic/tie-breaker*, **never** as a hard gate — code that drops the plain-comma form is still a bug. Keep the correctness path separator-agnostic; treat `=>` only as extra signal on top.

## Inheritance & frameworks

- `packages: HashMap<String, PackageFacts>` — ONE entry per package holding everything the file declares about it: `parents` (unified from `use parent`, `use base`, `@ISA`, `class :isa`, `class :does`, `with` (Moo/Moose), `__PACKAGE__->load_components` (DBIC)), `uses`, `framework`, `requires`, `is_role`, `dynamic_parents`. Read through the accessors (`declared_parents`, `package_uses`, `package_framework`, `role_requires`, `is_role_package`, `has_dynamic_parents`, `package_parent_edges`); `LocalParents` / `PackageFrameworks` are the seams that let the ancestry walkers and `BagContext` read either this table or the builder's still-accumulating walk-time maps.
- `resolve_method_in_ancestors()` — DFS parent walk (Perl's default MRO), depth limit 20. `MethodResolution::Local { class, sym_id }` vs `CrossFile { class }`.
- Parent enumeration has exactly two component spellers: `real_parents_of` (local ∪ cross-file) and `app_surface_parent` (the synthetic `APP_SURFACE_CLASS` edge for manifest-declared `app_surface_consumers` — the Mojo helper/plugin "app surface", `docs/adr/plugin-system.md`). `parents_of` composes both for the direct enumeration sites (`collect_ancestor_methods`, the `PackageSymbol` walk in `model/witnesses/`); `GraphView` derives them as separate edge kinds (`INHERITS` vs `APP_SURFACE`), so full-MRO walks (`for_each_ancestor_class`, SUPER, the implementations fan-out) pass `INHERITS | APP_SURFACE` while surface-excluding walks (trigger views, role-requires, the isa gates) pass bare `INHERITS`. The consumer set rides `FileAnalysis.plugin.app_surface_consumers` (baked from the plugin manifest) and `BagContext`.
- `complete_methods_for_class` walks ancestors, dedups by name (child shadows parent).
- Frameworks (`FrameworkMode::{Moo, Moose, MojoBase}`) detected per-package from `use`. **Which modules grant Moo-family `has` semantics is plugin-declared**: the `framework_mode_makers()` manifest in `frameworks/moo.rhai` (module → flavor + exported keyword surface; moo.rhai's `triggers()` is derived from it, so the plugin's accessor-option gate and the native-synthesis gate cannot drift); the builder bakes module → (mode, keywords) at plugin load and `visit_use` looks consumers up — core holds no module list. Mojo::Base stays a structural core arm (`-base`/parent args, not a name match). `has 'name' => (...)` synthesizes Method symbol + HashKeyDefs (constructor key + internal hash key). `isa` constraints map to `InferredType` (`Str`/`Int`/`HashRef`/`InstanceOf['X']`/...). Mojo::Base accessors get fluent `ClassName(current_package)` return. **Accessor-option vocabulary (`predicate`/`clearer`/`writer`/`reader`/`builder`/`handles`) lives in `frameworks/moo.rhai`, not core** — core's `extract_has_options` walks the `has` CST (rule #1) into a decision-ready `CallContext.has_options`; the plugin owns "which keyword → which method name + return edge". New Moo behavior goes in the plugin. The default accessor / isa / constructor-key synthesis is still native in `visit_has_call` (a larger move; this seam is the path for everything past it). **Role-ness is plugin-declared too**: the `role_makers()` manifest (base engines in `frameworks/moo.rhai`) feeds an open set; the builder bakes the per-package verdict as `PackageFacts::is_role` and `is_role_package` reads it — core holds no engine list (`docs/adr/role-contracts.md`).
- DBIC: `__PACKAGE__->add_columns` / `has_many` / `belongs_to` / `has_one` / `might_have` synthesize accessors with typed returns.
- Synthesized methods are standard symbols — completion/hover/goto-def/inheritance just work, including cross-file (resolver runs full builder).

## Workspace indexing

- `workspace_index` indexed at startup (Rayon `par_iter`, `.gitignore`-aware via `ignore` crate, 1MB cap, `catch_unwind` per file). Perl workspace files persist to `modules.db` (`source='workspace'`, path-keyed) with ref rows; warm starts stream valid rows (`warm_cache_streaming`) and skip re-parsing; resident copies are bag+refs+symbols-evicted once persisted (rehydration via the hub's blob LRU; registration feeds + the edge-index name records are extracted PRE-strip, and stripped fresh copies register in the persist writer AFTER their chunk commits, so an evicted copy is never reachable before its blob can rehydrate it). Standard extensions (`*.pm`/`*.pl`/`*.t`) are type-pruned at the walk; extensionless ENTRYPOINT scripts (`#!/usr/bin/env perl` — Mojo::Lite apps where `plugin 'X'` loads live) are found by a SHALLOW shebang scan over root + `bin/` + `script/` (`scan_entrypoint_scripts`; its `extra: &[String]` param is the seam for a future workspace-config `entrypoint_dirs` — callers pass `&[]` today). Don't broaden the entrypoint scan to a recursive walk — it would enumerate non-Perl source trees.
- File watcher via `workspace/didChangeWatchedFiles` for incremental updates (`spawn_blocking`).
- Query priority: `documents` (open, freshest) → `workspace_index` (all project files) → `module_index` (external @INC).
